## 1. 范围与完成定义

### 1.1 项目约束

- 沿用现有 Vue、Node、Python、文件数据与发布方式，保持蓝橙设计语言、角色双色和已有页面信息架构。
- 保留既有 URL、查询参数、旧链接解析、浏览器历史、上下文返回、播放队列、歌词、图谱和原图操作。
- 保留人工订正、已确认的身份与原始署名。近似姓名不自动合并；人员与机构按已经确定的独立署名规则处理。
- 新闻仍每 30 分钟更新，其余资料每日增量；来源失败单独重试，其他来源继续推进。
- 只使用免费公开来源和本地解析，不引入付费模型、审阅台、新的数据库或通用采集平台。
- 活跃代码兼容现有 Windows、macOS、Linux 工作方式。路径从项目或配置解析，不写死个人 checkout。
- 正式图片、唯一来源证据和用户文件保留；临时文件在任务结束时清理，不以文件扩展名批量删除。

### 1.2 每项关闭的条件

已复现问题先保留一个能够失败的行为用例，修复后验证正确结果。边界风险验证触发条件与恢复路径。自动化缺口验证真实来源采集、入库、目录生成及页面展示的完整链路。优化项测量前后数据量与交互开销。清理项确认运行时、生成器和维护入口均不再引用后删除。

无法识别的来源结构、未公开事实和无法唯一匹配的身份保留明确状态，不标成更新成功，也不制造关联。来源恢复或资料公布后能够继续补齐。只有临时错误有界等待、旧资料可读、恢复后新版实际出现，才能算恢复机制完成。

## 2. 代码拆分与维护规范

当前超过 3000 行的手写代码有：`uma_tools/app.js` 3997 行、`uma_tools/update_events.py` 3907 行、`uma_tools/app.css` 3678 行。主 HTML 为 1237 行，服务入口为 1312 行，也存在职责混杂，需要随相关迁移一起收敛。

### 2.1 前端按业务域拥有状态和视图

`app.js` 收敛为启动入口；应用壳、路由、各业务域、请求与缓存、播放控制各自维护。建议目录为 `uma_tools/frontend/`，具体文件名随真实依赖关系确定。

- `shell/`：主导航、页脚、页面标题、应用启动和通用加载状态。
- `routing/`：路由解析、旧地址兼容、历史记录、上下文返回和滚动恢复。
- `domains/news/`、`music/`、`events/`、`characters/`、`voice-actors/`、`anime/`、`staff/`、`horses/`：本域视图、状态、查询、详情和生命周期。音乐内部按歌曲、专辑、创作者拆分。
- `shared/`：请求、缓存、身份查询、日期格式和确实被多个业务使用的组件。
- 播放器保持独立生命周期。跨页导航不销毁播放和队列；各页面提供明确的曲目、录音与来源上下文。
- 跨域跳转通过路由，跨域事实通过明确的查询接口取得。业务模块不互相修改私有状态，不用全局对象作为新的依赖总线。
- 旧 `window.*` 入口只保留仍有调用者的兼容适配；调用者迁移后删除对应适配。

业务页面逐步拥有自己的模板。角色卡改为可复用的 Vue 渲染，保留原卡片外观、角色排序和非马娘分组。入口不再返回数百个业务方法；业务 CSS 与视图按路由加载。

浏览器模块使用原生模块能力，服务端继续使用现有 Node 模块方式。发布器必须正确处理入口、静态模块依赖、动态路由加载和血统 iframe；同一套源代码在普通本地预览与发布目录中均可运行。

### 2.2 Python 分离采集、身份、合并和生成

`update_events.py` 收敛为兼容 CLI 与流程组装。事件工具包分别承担：

- 身份解析：角色、声优、外部嘉宾、人员与机构。
- 来源采集：官网新闻、节目频道、广播、活动来源和人物资料。
- 资料合并：人工值、自动字段、来源订正和场次粒度。
- 活动与场次生成：日期、名单、身份、歌单和媒体。
- 音乐生成：歌曲、录音版本、发行曲目、署名与歌词引用。
- 出演与合作索引：角色、声优、创作者的反向关系。
- 输入输出与资料验证：统一编码、原子写入、引用检查和兼容旧命令。

`crawl_horses.py`、`sync_music_metadata.py` 等超过千行的模块，在本次涉及的领域拆开解析器、来源客户端和资料合并。纯解析函数不发网络请求，导入模块不启动任务，来源客户端不直接发布生成目录。

### 2.3 Node 与样式按职责拆分

- `server.js` 保留配置、服务组装与启动；目录 API、新闻服务、翻译服务、图片缓存、音频代理和调度各有模块。
- 通用 HTTP 响应、取消与时间预算复用小型公共工具。保留音频范围请求、允许来源检查和既有错误处理。
- CSS 分为 token 与基础、站点壳、控件、实体与关系列表、业务样式。响应式规则靠近对应组件，删除已失去调用者的覆盖规则。
- 全站共享搜索、下拉、分页、播放／加入按钮和加载／错误组件；个别业务需要的变体通过明确参数表达。

### 2.4 可维护性的验收

手写源代码不再存在超过 3000 行的文件。启动入口目标在 300 行以内，业务文件通常为 200–800 行；超过 1000 行时检查是否承担多种职责。生成数据、第三方库和合法的大型来源文件不按手写代码拆分。

每个模块有清晰的输入、输出与生命周期；公共接口用 JSDoc 或 Python 类型注明。保持既有代码风格，集中消除无用兼容分支和重复规则，不做全仓纯格式重写。拆分后的依赖无循环，旧实现随迁移删除，不留下两套长期运行的逻辑。

### 阶段 2 提取模块并修正请求与缓存生命周期

对应问题 41–45、59、60，以及第 2 节的结构目标。

按一个业务域迁移一个业务域，每次迁移验证原有路径后删除旧实现。请求去重保留独立订阅者取消语义；只有没有订阅者或整体预算到期时才取消共享网络请求。

缓存失效同时约束正在进行的请求，旧结果不能在失效后写回。可变数据有期限、来源修订与重新校验机制；页面重新激活或进入相关栏目时按需更新。角色与马匹的可变 JS 逐步由明确的数据接口读取，仍有使用者的旧数据入口保留兼容。

动画与其他目录统一采用完整快照读取。异常输入保留最后完整资料并报告失败；正确新资料到达后自动采用。慢请求、快速切页、重复重试、来源修订切换均不能把旧实体结果写到新页面。

### 阶段 3 新闻翻译与图片恢复

对应问题 7、10–15、46、50。

标题和正文共用数字事实处理：识别日期、时刻、小数、金额、比例和编号，翻译前保护，返回后核验。只允许可证明等价的格式变换；`1.5→15`、错误时间和增减数字均拒绝。

原文获取与中文翻译分离。先提供可读的文章，中文完成后更新对应内容，保持阅读位置。翻译任务有优先级、整体期限和取消语义，长正文不会被所有标题补译串行堵住。完全未翻译的日文与半译结果保持未完成状态，不能进入完整中文文章缓存；已成功的片段可复用，失败片段继续重试。

翻译缓存损坏时保留可用部分或旧值，隔离损坏缓存并重新生成；不覆盖人工订正，不让服务反复启动失败。正文订正仍绑定对应原文，旧请求不能覆盖新原文。

原图首次加载、重试、切图与关闭有明确的状态和期限。原图失败时保留可用预览；超时恢复可操作状态，关闭时释放图片任务、定时器和事件。来源恢复后真正显示原图；连续切图不叠加错误框、不出现空白画面。

新闻图片采用过期缓存可读、后台重新取得的方式，保留失败重试；刷新成功后更新实际图片。缓存默认容量目标为 256MiB，配置可调整；只清理可重新获取的新闻缓存，按近期使用与有效引用保留。正式资源和唯一证据不参与这一清理。

### 阶段 4 活动、音乐与人物资料的自动更新闭环

对应问题 5、6、16–31。

采集结果区分已更新、有效无变化、部分失败和失败。成功必须有来源响应、结构识别与处理结果；工具缺失、空解析和请求失败不能算无变化。部分成功资料可以发布，但失败来源继续重试。依赖目录在实际输入变化时重建，避免失败任务反复全量重建。

修正编号公演索引，让它直接读取资料源。安装并检查免费节目采集所需工具；频道发现、资料解析和来源恢复均运行验证，不能只验证依赖存在。已有缺失字段、尚未公布日期与名单的活动定期重访。

活动发现从企划官网、既有节目和组合来源扩展到本站已登记声优／嘉宾的公开相关活动。来源按发布日期、活动日期、场次和出演身份解析；只收录与本站企划有关的资料。个人来源采用有界队列与增量游标，控制请求量。

歌单识别有实际数据的相关工作表，不依赖第一个页签。新活动与场次先由明确资料建立，再在日期、场次、人员和曲目可唯一核对时补歌单。保留已有精调表格，无法唯一匹配时留下具体待补字段，继续寻找其他公开来源。

专辑类型来自明确发行信息与规范分类，数字单曲统一为单曲。专辑的曲目、封面、署名和音源分别维护完成状态，已有曲目不阻断以后补音源。待补队列按最近尝试时间轮转，失败条目不长期占用前六个位置。

网易云与其他音乐来源的无结果有复查期限，后续新增资料可补齐。同岗位多人按岗位与人员组合合并，不丢第二位作曲者；不以模糊匹配混入另一录音。缺失歌词、署名和音源分开重试。

角色、声优、原型马与血统按缺失字段刷新，不以已有整条记录作为永久跳过依据。自动字段可根据明确的来源订正更新；人工值和人工身份保留优先级。新增固定身份的非马娘角色继续进入同一资料链路。日期、名单、音源缺失与来源不可达有不同的重试条件。

验收包括真实来源运行、离线与限流模拟、资料后公布、失败后恢复、超过队列额度、多个工作表、新活动／场次、同岗位多人和人物资料回补。

### 阶段 5 动画、机构、音乐关联与片尾识别

对应问题 32–39。第 40 项骑师资料库属于 #13，不在本阶段实现。

识别出的事实保留来源 URL、作用范围、时间位置及必要的最小证据帧。重复取得的片段和无用帧立即删除；中断任务的遗留文件按专用临时目录清理。按片段处理与资源预算分批，避免下载整集和占满磁盘。

已确认姓名不因 OCR 近似结果被替换或归并。真实疑项集中沟通，不建立审阅台。来源恢复、识别器改进或文字资料出现后可从已有进度继续补齐。

验收至少覆盖人员／机构并列、同岗位多人、纵向滚动署名、两个相近但独立姓名、剧集缺口补齐、新作品封面失败恢复，以及音乐版本与观看资源状态变化。文字解析、提帧、OCR、入库和页面显示分别有可执行验证。
