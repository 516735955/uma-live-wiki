# 赛马娘演出综合站：未来发展主题地图

更新日期：2026-10-14。本文是项目唯一的长期 roadmap，只维护尚未交付的需求、剩余工作与未来可能性。最初建立于 2026-09-13；原聊天附件位置与根目录 ROADMAP.md 只保留本文入口。

## 维护工作流

1. **开工先读本文，再核对现状。** 同时阅读相关批次计划、最近用户决定、Git／PR、数据、页面和更新工具。旧计划不能证明功能仍未完成，聊天里的“完成”也不能代替实际交付证据。
2. **用户明确要求做的内容立即加入。** 放入相应主题，写清范围与完成条件；已归属当前批次的事项只保留一个主条目，具体页面、字段和实施步骤链接该批次计划。Agent 的未确认建议放在“未来可能性”，不当作已经授权的开发范围。
3. **部分完成只保留剩余工作。** 数据、页面、关联、更新或部署中仅完成一部分，就改写为缺少的部分，不继续挂着“重建整个资料库”。本地已验证但尚待合并／发布的功能只保留交付收口，不重复列实现任务。
4. **交付后删除，取消后移除。** PR 合入 main，且所需数据、页面、关系、更新和发布均验证可用后，删除对应建设项。取消、永久排除或被新决定替代的内容移出待办；必要边界保留在“长期边界”。Roadmap 不设“已完成”专区，历史由 Git、PR 和原实施文档保存。
5. **维护与交付同步。** 准备 PR 时依据本批实际差异删减待办；合并后核对 main 与必要的线上行为，清除剩余收口项。主线临时修复也按同样规则更新。来源暂时不可达、已知缺项与未实现功能分别说明，不因一次失败扩建治理平台。
6. **只修改一份主地图。** README、根目录 ROADMAP.md、旧聊天附件都指向本文，不另建独立长期待办。批次计划记录本批规格与验收，不取代本文；新发现的跨批次事项回写本文。
7. **并行协作先读最新文件。** 每次修改前检查 Git 与文件现状，只编辑所属主题，保留其他任务的新内容，不用旧副本整篇覆盖。归属变化时同时更新主条目和批次引用。
8. **完成判断写进本批验收。** 在提交／PR说明中给出具体实现与必要验证，本文只留尚未完成的结果要求，不建立额外完成日志、版本树或审批门禁。

当前常规维护沿用项目既定 Git 工作流。本文不改变各聊天已取得的实施、推送、PR 或部署授权；本次合并文档也不表示 #12、#13 已交付。

## 未来可能性地图

以下保留原地图的能力上限，供未来选择主题；不代表当前全部开工。已经完成的基础档案、资料库、播放器队列、血统查看、动画作品／单集／参与履历和共享展示不重复列为待建项。各项进一步立项时先核对最新实际功能，只建设剩余部分。

### 1. 全站公共能力

- 在已有稳定实体上补齐尚未接入的场馆、商品、组织、社交与图片身份，不重新生成现有角色、人物、马匹、歌曲、发行与活动 ID。
- 将本域检索扩展为跨库搜索，支持中文、日文、英文、旧译、昵称与罗马字，标明命中实体和位置。
- 完善新主题的来源、时间、外链与反向关系组件，沿用现有路由和返回上下文。
- 扩展人物、作品、活动、商品与地点的分享预览；已有栏目深链继续复用，#13 保持无分享按钮。
- 在有实际需要时提供公开资料修订／新增内容、RSS、日历订阅、可导出的个人数据或只读查询。
- 按实际地区发行资料补充语言与地区维度，不把全站多语言作为当前中文资料建设的前置条件。

### 2. 角色与企划世界

- 补录尚未进入当前角色库的官方漫画、游戏、舞台角色和重要配角；继续使用同一身份与译名体系。
- 将现有静态舍友资料扩展为有来源的宿舍关系，进一步整理队伍、班级、学生会、家族称谓、朋友与竞争关系。
- 建立角色关系网络、宿舍／队伍浏览、主题分组、角色对比和关联路径，明确作品与版本语境。
- 补充漫画、游戏、舞台和商品履历；已有动画、歌曲与活动参与不重新建库。
- 建立角色公开、实装、登场、生日视觉、服装和商品时间线。
- 建立服装档案，关联立绘、游戏版本、作品画面、现场服装与商品。

### 3. 声优与企划参与者

- 补齐尚缺的公开人物字段、可靠照片、所属历史、官网账号与访谈入口，不重新建设已有声优页。
- 在既有歌曲、动画和活动参与上补充相关广播、公开访谈与照片，不扩成与企划无关的完整娱乐履历。
- 利用真实共同演唱、出演与节目记录呈现搭档和巡演关系，不将同台推断为私人关系。
- 支持生日、已确认出演与发行关注；个人关注先采用浏览器本地资料。
- 事务所与唱片公司资料如另行立项，先明确页面价值；动画机构不因出现在 Staff 中自动建设原子页。

### 8. 音乐、版本与创作者

- **歌词剩余体验**：现有歌词正文、版本选择、译文切换和时间轴数据继续复用，尚待播放同步高亮、当前行定位与点击歌词跳转；独立阅读入口按实际使用需要设计，不再归入已完成 #11 的动画批次。

- 在既有创作者合作图上扩展角色、声优、作品和演出的可解释路径，不另建同一种合作图谱。

- 提供角色／卡片收藏、歌曲解锁、剧情阅读与队伍规划，先明确资料来源和更新方式。

### 15. 新闻、日历与主动提醒

- 在已有新闻服务上扩展正式作品、音乐、厂商、事务所和场馆来源及实体关联；现有新闻故障修复归 #12。
- 统一生日、纪念日、节目、活动、作品／音乐／商品发行与预约的日期事件，生成“今天”“接下来”和日历。
- 精确时刻保留时区，仅日期不虚构午夜，待定不产生精确提醒。
- 本地关注角色、声优、作品、活动、商品类别与地区，提供个人行程、导入／导出及 iCalendar／RSS。
- 可选外部提醒与每周新增资料／修订汇总，沿用同一事件身份，不重复通知同一公告。

### 16. 搜索、图谱、统计与专题

- 全局检索作品、单集、角色、人物、歌曲、地点及商品，标明命中位置，复用规范名与别名。
- 共同歌曲／出演／作品／比赛、真实血统和关联路径查询归后续探索／娱乐方向。
- 建设有明确统计范围的演出变化、参与覆盖、赛事趋势、合作与年度回顾；不恢复已取消的无用出演次数排行页。
- 按日期探索当时已公开的资料，提供时间机器、地图探索、随机发现与轻量关联推荐。
- 补活动场次、录音、歌单行、媒体、岗位／人物和血统节点的准确定位，实体更名／排序后仍恢复上下文。
- 事实型三冠、经典世代、传承、创作者合作与巡演主题可引用规范资料；作品解读与剧透不作为默认新增内容。

### 17. 同好个人功能与共建

- 本地收藏角色、声优、作品、马匹及最近浏览，不推断站外播放或阅读完成状态。
- 保存参加／观看／想参加的活动，拥有／预订／想要的商品及作品阅读进度。
- 提供可导出、导入、分享的个人资料，不以账号系统为前置条件。
- 复用现有订正入口补来源、照片与具体字段；#13 的上下文定位先交付，不另建一套重复表单。
- 贡献者记录、资料讨论与投稿展示作为潜在方向另行确认，不把新审阅台作为自动更新前提。

### 18. 数据维护与长期运营

- #12 完成当前来源更新、缺项回补、请求恢复和发布可靠性；新主题沿用这些工具，不重新建设通用采集平台。
- 为新来源明确字段职责、来源身份、适用时期和人工值优先级，唯一匹配时补空值，明确自动事实可按已确认来源订正。
- 持续核对新主题的身份、关联、图片归属、缺失引用与资料冲突；新增检查围绕真实失败，不建立冻结契约或额外门禁。
- 失效视频、销售结束、公开参观和账号变化分别保存来源观察，未知不冒充无变化或已失效。
- 素材保留原始地址、本地路径、关联实体与更新时间，补图与重新生成使用同一链路。
- 用户确有需要时提供公开资料更新页；内部维护保持现有脚本与简单工具，不强制人工审批每次自动同步。

## 长期边界

- 围绕赛马娘企划及直接相关音乐、演出、作品、真实赛马与商品建设。未来可能性只有经用户选定才成为实施批次。
- 保留稳定身份、原始事实、来源、人工中文、Google Doc 已确认资料与精调歌单；不为统一模型批量覆盖已有成果。
- 角色、现实马、表演／制作参与和作品设定分别表达，真实马的亲缘不等于作品角色的家庭关系。
- 马主永久不建设目录或原子页；厩舍、训练基地仅为马匹字段。俱乐部指现实俱乐部／集团，赏金仅属于马匹与比赛。
- 非原型参赛马只建设基础卡片与必要关系资料，不能由完整赛果自动扩建独立页。牧场、俱乐部、骑手和调教师的关联名单聚焦已登场原型。
- 动画时间线、独立动画公司页／机构筛选、逐镜考据、作品解读与剧透模块不恢复为待办。当前动画关联只连接明确比赛与单集。
- 不提供投注、预测、赔率推荐与博彩导流；历史赛果的赔率属于资料字段。
- 人物只收录公开且与企划有关的资料，不扩展私人生活或传闻；牧场见学按官方规则与核验时间说明。
- 商品不承担二手估价与交易；游戏工具不制作游戏自动操作或破坏公平性的功能。
- 内容页面继续复用本站导航、Hero、分栏、筛选、人物标签、颜色、图片与播放器组件；零构建 Vue、Node、Python 和跨平台维护方式继续作为基础。
- 工程验证与本项目实际风险相称，不为假设场景增加安全合规项目、来源迁移、凭证治理或企业级发布工程。

## 来源职责与选题参考

以下是原地图保留的研究入口与各主题来源分工，不表示已重新核验所有外站的当前内容。正式实施时核对当时具体页面与事实。

- **角色与正式内容**：赛马娘官方角色、Contents、作品站决定当前公开事实与正式身份；漫画、舞台及地区版本采用各自出版社／制作方资料。[角色](https://umamusume.jp/character)、[Contents](https://umamusume.jp/contents/)
- **作品参与与观看**：作品官网、逐集原署名、正式平台资料分别决定标题、日期、Cast／Staff 与观看入口；官方资源和关系证据分别维护。[RTTT](https://umamusume.jp/contents/anime/roadtothetop/)
- **音乐与发行**：Lantis 等正式发行页决定曲目与署名，J-WID 用于歧义核对，MusicBrainz 补充开放标识，不压过已确认资料。[Lantis](https://www.lantis.jp/release-item/LACA-9814.html)、[J-WID](https://www2.jasrac.or.jp/eJwid/main?trxID=F00100)、[MusicBrainz](https://musicbrainz.org/doc/MusicBrainz_API)
- **比赛与马匹**：JRA／NAR 决定当场结果，JBIS、登记资料与其他可靠来源补血统、生产者和历史身份；Wikidata 可作跨库线索。#13 使用免费公开来源，不依赖付费、仅限 Windows 的数据库。[JRA](https://www.jra.go.jp/)、[NAR](https://www.keiba.go.jp/)、[JBIS](https://www.jbis.or.jp/)、[Wikidata](https://www.wikidata.org/wiki/Wikidata:Data_access/en)
- **牧场与见学**：案内所、牧场官网与项目官方说明决定公开所在地、项目和当前开放条件。[竞走马故乡案内所](https://uma-furusato.com/)
- **活动与节目**：主办方决定名称、日程与场馆，企划正式资料证明出演关系，票务来源只决定其销售条件；公开频道提供节目身份和媒体元数据。精调歌单保持既定来源优先级。[YouTube 数据说明](https://developers.google.com/youtube/v3/docs/playlistItems)
- **人物**：本人、事务所和唱片公司决定公开人物字段和账号，不强补未公开年份。[俳协示例](https://haikyo.co.jp/profile/profile.php?ActorID=12722)、[Machico 官方资料](https://columbia.jp/artist-info/machico/prof.html)
- **商品与渠道**：官方发布证明联动和发布，厂商决定 SKU、规格与再版，销售页面决定渠道状态，资料层与临时销售状态分开。[官方 Goods](https://umamusume.jp/goods/)、[RTTT Goods](https://umamusume.jp/contents/anime/roadtothetop/goods)
- **社交与地图**：公开账号、原始帖文及官方设施资料负责身份与时间，OpenStreetMap 可补坐标；照片和帖子保留上下文。[Overpass](https://wiki.openstreetmap.org/wiki/Overpass_API)、[X 查询文档](https://docs.x.com/x-api/posts/search/introduction)
- **社区与中文线索**：Umamusu Wiki、Fandom、萌娘百科和 GameTora 用于覆盖缺口、中文检索词与关系发现，不直接覆写规范实体。[Umamusu Wiki](https://umamusu.wiki/)、[Fandom](https://umamusume.fandom.com/wiki/Umamusume_Wiki)
- **体验参考**：LL-Fans、Bandori.Fans、Bandori Party 用于日期、图鉴、服装和互链；genchi.collector 可参考活动／场次／时间节点，SeatView 可提供场馆外部视野入口。按具体需要借鉴，不照搬平台或审批流程。[LL-Fans](https://www.ll-fans.jp/data)、[Bandori.Fans](https://bandori.fans/zh-Hans/database)、[Bandori Party](https://bandori.party/costumes/)、[genchi.collector](https://github.com/StarSailAI/genchi.collector)、[SeatView](https://seat.genchi.top/zh/)

正式资料归一后由现有生成器提供页面所需目录与详情。生成数据不是第二个编辑入口；多来源用于核验一条事实，不能在前端各自提供相互矛盾的答案。
