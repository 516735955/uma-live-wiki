# 内容状态规范

这是全站内容状态的唯一产品规范，适用于资料库、原子详情、新闻和后续新增功能。判断顺序为：内容事实、页面层级、展示方式、统一文案。内容页把“正在读取”“请求失败”“尚未收录”和“证据确认为空”分开表达；没有来源证据时只能使用 `uncollected`，不能把缺数据推断成“官方尚未公布”或“已确认没有”。

## 组件 API

```html
<content-state
  state="uncollected|not_announced|not_published|not_applicable|confirmed_none|loading|error|filtered"
  subject="创作资料"
  :retry="true"
  @retry="..."
  :clear="true"
  @clear="..."
/>
```

组件默认 `state="uncollected"`，使用 `ui-state compact` 的普通一行样式，不强制图标或卡片。`error` 优先于 `loading` 和空原因；`retry`、`clear` 只有页面确实有对应操作时才传入。

| 状态 | 统一句式 | 使用条件 |
| --- | --- | --- |
| `uncollected` | 尚未收录{subject} | 没有内容且没有更强证据 |
| `not_announced` | 官方尚未公布{subject} | 一手来源明确说明尚未公布 |
| `not_published` | {subject}未公开 | 来源明确说明内容未公开 |
| `not_applicable` | {subject}不适用 | 内容类型明确不适用，例如全版本明确为 instrumental 时的歌词 |
| `confirmed_none` | 已确认没有{subject} | 有明确依据确认不存在，空数组及生成记录为零不足以确认 |
| `loading` | 正在加载{subject}… | 请求或异步补全进行中 |
| `error` | {subject}加载失败 | 请求失败；可以重新读取时提供重试 |
| `filtered` | 没有符合条件的{subject} | 数据已加载，但当前筛选没有匹配项 |

## 四层级与页面规则

1. **整站入口**：已开放资料库保留入口，空时解释内容状态；未建设的骑师资料库不放正式导航，其旧链接保留“尚未收录骑师资料”。
2. **原子页核心栏目**保留稳定入口。歌曲的收录信息、创作信息、歌词、出演记录等核心 tab 不因本站缺资料而跳转或删除。明确不适用时才隐藏入口：全版本明确 `instrumental` 才隐藏歌词，但旧歌词路由显示“该录音为纯音乐，无歌词”，不改 URL。血统使用已有来源的 `mapping_kind` 区分原型马、原创角色、非马娘角色，不能把找不到原型马链接直接当成不适用。
3. **补充关联模块**无内容时整体隐藏，含标题、边线和操作，例如合作关系、动画关联、观看资源、推荐视频、原型马生涯分节。用户通过旧链接明确请求隐藏栏目时，在原上下文解释缺失原因。补充区请求失败仍显示错误和重试，不把失败误当空数据。
4. **字段级信息**：核心身份字段保留标签并说明缺失状态；可选字段为空时隐藏。`—`只作紧凑表格缺值符号。生日来源明确未公开时显示“未公开”，未查到时显示“尚未收录”。图片沿用现有默认封面、人物占位或文字hero，不为每个缺图新增大提示框。

实体列表属于用户操作反馈：首屏加载、请求失败、基础数据为空和筛选无结果互斥。实际有搜索或筛选条件时才用 `filtered`；清除动作必须重置所有相关条件并回到第一页。没有筛选却没有数据时用 `uncollected`。已加载的数据在刷新时可以继续显示，不能把待返回的请求先显示成“没有记录”。

歌曲 credits 只有存在 `display_credits` 的版本才渲染；例如原版为空、variant 有作曲者时只显示 variant，不显示空原版行；整首 0 credits 时使用“尚未收录创作资料”。专辑无曲目时读取 `content_status.tracks.state`，证据不足使用 `uncollected`，不显示 `0 首` 或空表，也不制造音频操作。

数量为 0 只说明当前数组为空，不能单独推出 `confirmed_none`、`not_announced` 或 `not_published`。`unknown`、缺失字段和未采集结果统一走 `uncollected`；只有源数据明确标记的 `content_status` 或等价一手证据才能升级状态。真实例：没有现场演出数组的歌曲显示“尚未收录演出记录”；全版本 `instrumental: true` 的歌曲在旧歌词路由显示“该录音为纯音乐，无歌词”。

取消、延期是活动事实，不是普通空状态：保留活动及公告；已取消活动隐藏歌单，不用“尚未收录曲目”代替取消说明。缺中文译文用“尚未收录中文译文”；只有实际处于翻译或归档任务中才显示处理中，不承诺未经安排的补全时间。

## 数据、组件和视觉约束

- 持久资料可以在实体的 `content_status` 中标注分区状态，例如专辑的 `content_status.tracks`；事实性状态同时记录 `source_url` 和核实日期 `checked_at`。请求的 loading/error 不写入资料事实。
- 有可展示内容时优先展示内容。录音对象存在不等于存在署名；空表格、表头、上下边线、分页不能代替空状态。
- 普通空态使用公共组件的一行文字。只有实际能执行操作时才提供重试或清除；不为每个空块增加插画、装饰图标、宣传语或订正按钮。
- `subject` 使用页面已有名词，例如“创作资料”“曲目”“演出记录”；不要传入完整句子，也不要自行改写默认句式。
- `reason` 仅用于确需说明已确认业务事实的特殊情况，例如纯音乐无歌词，不用于各页面任意重写普通空文案。

## 当前栏目登记

- 歌曲：收录、创作、歌词、出演记录为核心；动画关联为补充。
- 专辑：曲目为核心，数量未知不显示“0首”；动画关联为补充。
- 角色、声优：资料、歌曲、动画出演、活动出演为核心；血统根据明确适用性决定入口；原型马视频为补充。
- 动画：作品/剧集实际支持的栏目按数据生成入口；隐藏栏目的旧链接仍解释状态，筛选不得改变原始可用性判断。
- 活动：场次和出演阵容按已有资料展示；曲目仅在存在实际曲目时展示整块组件，不为没有歌单的谈话、角色节目生成空框或曲目提示。已有曲目但无试听仍保留曲目。视频、动画关联、未分场补充出演者按内容显示；取消状态优先隐藏曲目。
- 创作者：有歌曲作品时展示参与歌曲；合作、动画制作、动画音乐按实际内容展示。只有动画制作关联的人没有歌曲记录也是有效页面。
- 制作人员：身份资料为核心，关联作品为补充；空关联不创建空section。
- 原型马：身份资料为核心，简介、生涯、成绩、比赛、奖项、退役信息按已有资料展示。
- 新闻：正文是核心；原文/译文缺失、归档处理中和读取失败分别处理。静态联系、政策、条款、订正和友链不虚构异步资料状态。

## 活动、动画与关联记录的统一展示规则

- **父活动与场次**：父活动 Hero 只承载活动级身份、总日期、地点和系列信息；场次/赛程选择器放在 Hero 内。选中的子单元只替换自身的封面、简介、日期时间、出演阵容、媒体和曲目，不把其它场次或父活动的阵容复制进来。旧的场次 URL 必须解析为父活动并预选对应子单元；无显式子单元参数时才使用默认场次。
- **场次标签**：选择器文本必须包含业务类型（赛程、分集或场次）、原始标签（例如 DAY1）和实际日期；不要用泛化的“详情”替代可核对的场次名。取消状态属于活动/场次事实，优先于普通空态；取消时隐藏曲目组件，但保留取消公告和已有出演资料。
- **曲目块边界**：实际曲目为空时，整个曲目块一起隐藏，包括标题、日期工具栏、表头、边框和“暂无曲目”占位。已有曲目但试听链接为空时仍展示曲目资料，不把“无音频”误判为无曲目。
- **时间**：所有活动、动画播出和公开渠道使用同一时间格式化组件。日本时间 `24:00` 及以上必须换算为实际次日日期后再显示；例如 `2018-04-01 24:00` 显示为 `2018-04-02 00:00`。首播/首发为主时间，其它渠道在可展开的补充区显示；未知时间不编造时分，也不把播出时间称作开演时间。
- **历史记录**：角色、声优和创作者的同类出演历史复用统一记录组件。父活动下的多个子场次应聚合为一条父活动记录，同时保留实际出演的子场次标签和可跳转链接；不能因聚合而丢失边界，也不能把仅有父活动关系误当成每一场都出演。
- **动画作品与发行版本**：作品层记录用于表达作品中的 OP/ED/插曲使用范围；发行版本用于表达真正不同的录音、剪辑或发行载体。相同录音的多个发行应合并为一个作品用途条目，并在发行详情中保留各发行；只有录音或版本确实不同才拆分。发行名（例如“原唱发行版”）不是用途标题，不能直接替代“片头曲/片尾曲”。作品级与单集级证据合并时必须保留单集范围并核对冲突，不能盲目并集。
- **统一搜索**：角色、声优、活动、动画等列表的文本搜索统一经过 `window.UmaSearch.includes`；页面只保留无公共实现时的兼容回退。搜索词、排序和筛选条件必须进入 URL，并在刷新、前进、后退及跨实体导航时恢复。
- **音乐分类**：“作品归属”表达音乐实际用于哪些作品，可同时属于多个作品；“发行系列”表达 STARTING GATE、WINNING LIVE、ANIMATION DERBY 等发行编制。独立艺人的动画主题歌同时保留动画归属与独立发行属性，不把两个维度混进同一选项。
- **场地身份**：原始地点写法映射到稳定 `venue_id` 与统一中文展示名。同一场地的英文、日文、旧称和标点变体复用同一 ID；同一设施的不同厅、不同巡演城市保持各自边界。线上播出与地区待定信息不建立实体场地。
- **每日更新**：采集保留来源原文，订正按稳定来源身份和字段合并；来源序号、列表排序与数组位置不能作为活动身份。已确认译文优先复用，百度只处理新文本或原文实质变化，无额度时保留待译。目录构建不联网，图片由采集步骤缓存后再生成展示资源。

## 实例

- WINNING LIVE 36曲目已公开：录入实际7首，不显示待公布，也不虚构试听地址。
- WINNING LIVE 37官网已公布8首曲目但封面尚未解禁：展示实际曲目；无音频的曲目保留资料，封面继续使用占位图。曲目和封面的状态独立判断。
- 原声带曲目署名缺失：优先补已核实的作曲/编曲；其余显示“尚未收录创作资料”。仅有发行艺人不能推断具体岗位。
- 本站没有收录演出：显示“尚未收录演出记录”，不能断言歌曲从未演出。

## 旧路由与接入核对

保留既有实体 URL、section 参数和返回位置。新状态只改变栏目内部展示，不替换旧链接，不把可重试错误转为空态。新模块接入时需要登记：所属页面、核心或补充层级、数据来源字段、默认状态、错误重试动作、旧路由行为和至少一个真实数据例。

新增功能或资料库的PR说明包含三项：栏目层级与来源、缺失状态及证据、有内容/无内容/失败和旧链接的执行结果。复用公共组件，运行共享状态测试与受影响页面的现有检查，再用浏览器验证真实交互。无需复制每个页面的同类测试，也不新增发布gate或冻结基线。

rebase取得本规范与公共组件后，功能实现继续遵循这里的规则；变更规则时直接修订本文件及相应公共实现，避免新增一份互相覆盖的规范。调试问题清单和本地验收记录不属于仓库规范，不提交到Git。
