# 角色与声优数据爬取流程（增量版）

> 总原则：现有 **179位角色 / 183位声优** 是底库，任何脚本都只处理增量、不重爬存量。
> 所有输出文件位于当前仓库根目录，脚本会根据自身位置解析路径；前端页面读取这些文件动态渲染，改完刷新即生效。

---

## 阶段 0｜检测新角色（入口）

| 项目 | 说明 |
|---|---|
| 数据来源 | `https://umamusume.jp/character/`（Nuxt SSR，解析页面内 `__NUXT_DATA__`）|
| 对比基准 | `character_index_data.js` 里现有 `id` 列表 |
| 输出 | 新角色清单：`id` / 日文名 / 英文名 / CV日文名 |

官方站只提供日文名与CV，中文名在阶段1从萌娘百科获取。

**🚦 门禁检查（先萌百后爬取）**：执行前先抓取萌百登场人物页，确认新马娘在萌百侧**已有对应条目和中文名**再开始入库；若萌百未更新，等待而非抢先入库（否则译名、详情页全部缺失）。实测脚本：`uma_tools/check_new_characters.py`（阶段0）+ 登场人物页解析。

## 阶段 1｜新角色入库（官方侧素材）

| 步骤 | 目标 | 说明 |
|---|---|---|
| 1.1 | `uma_official/{id}.png` | **卡片图**：官方 `{cid}_list.png`（296×389，与存量规格一致）|
| 1.2 | `uma_avatars/{id}.png` | 圆形头像：官方 `{cid}_icon.png`（200×200）|
| 1.3 | `character_index_data.js` | 追加条目：`id / zh / ja / en / cv_zh / cv / img / page(萌百链接) / main / sub` |

- **顺序必须与官方站一致**：追加后按官方页 id 出现顺序对整个 CHAR_INDEX 重排
- **中文名/CV**：从萌百登场人物页提取（如 エフフォーリア=乐透心、ファレノプシス=蝴蝶兰）；CV即使官方未发表，萌百也可能已收录（如浅见春那）
- **main/sub 颜色**：直接取萌百登场人物页该角色的主题色（比取色猜测准确）

## 阶段 1.5｜萌百立绘（角色详情用）

| 目标 | 说明 |
|---|---|
| `uma_moe/{id}.png` | 萌百登场人物页该角色的立绘原图（`UPDCH_XX_00.png`，去掉`!/fw/300`等缩放参数取原图），压缩至宽600，**保留透明通道** |
| `uma_avatars/{id}.png` | 头像200×200，由 `uma_tools/make_avatar.py` 生成 |

### 头像生成规范（make_avatar.py）

```
python3 uma_tools/make_avatar.py <cid> <透明立绘路径> [窗边长覆盖值]
```

1. 自动定位：头顶(首个非空行)/脸宽(顶部12%内最大跨度)/肩线(跨度>脸宽1.9倍处)
2. 方窗边长 = max(脸宽/0.55, 肩线距×1.15)，可按角色覆盖（如真诚=440）
3. 窗口 ×1.2 显示放大，头中心(头顶与肩线35%处)对齐画布中心
4. 主色圆底 d=195（四周留边）+ **右下投影**(高斯模糊) + 圆形软边蒙版
5. 800×800 超采样合成 → LANCZOS 缩至 200

⚠ 长发铺开型立绘（真诚）肩线探测会误触发，需手动覆盖窗边长；新角色生成后务必人工过目一次。

**🚫 铁律：`uma_moe/` 原件只读。** 头像生成等任何加工一律先**复制副本**到临时路径再操作，完成后删除副本。严禁把放大/裁剪/压平后的图直接写回 `uma_moe/`（曾因违反导致立绘尺寸偏离600×1056规范、详情页显示异常）。

## 阶段 3｜血统图（多源综合，半自动）

| 步骤 | 来源 | 输出 |
|---|---|---|
| 3.1 血统表 | **JRA**（jra.jp/JRADB/accessR.html）+ **umamusume.fandom.com**（角色页Real Live页签）+ **zh.wikipedia** + **ja.wikipedia**（各自的原型马页面）综合比对 | `血统关系_data.js`（PED_REL）|

⚠ 此阶段涉及马名跨站匹配，保留人工核对环节。旧管线脚本：
`scrape_pedigree.py → parse_pedigree.py → build_graph.py → gen_role_svgs.py → rebuild系列`

## 阶段 4｜新声优（由新角色的 CV 驱动）

**增量队列** = `CHAR_INDEX` 中出现过、但 `va_photos_data.js` 里没有的 `cv_zh`。

照片抓取优先级：

| 优先级 | 来源 | 取什么 |
|---|---|---|
| ① | 萌娘百科（pageimages缩略图）| 照片 + infobox生日 |
| ② | 所属事务所官网 og:image | 正式宣材照 |
| ③ | 推特头像（unavatar/wsrv代理）或手动 | 头像 |

处理规范：

- 统一压缩为 **300px 宽 JPEG q75** → `uma_va/va_{声优名}.jpg`
- 追加 `va_photos_data.js`：`{cv_zh: {img, page, title, birth}}`
- **卡片**：前端 `vaList()` / `renderVoiceList()` 动态生成，无需改 HTML
- **担当角色关联**：自动反查 CHAR_INDEX 中该 CV 的全部角色，详情链接指向 `/database/characters/{id}`；原声优（换过CV的角色）自动带 `原` 徽标
- 特殊情况：换过声优的角色在数据里填 `cv_former`(简体)/`cv_former_ja`(日文)
