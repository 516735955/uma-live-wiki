# 角色与声优数据爬取流程（增量版）

> 总原则：现有 **179位角色 / 183位声优** 是底库，任何脚本都只处理增量、不重爬存量。
> 所有运行数据位于当前仓库的 `data/` 目录，脚本会根据自身位置解析路径；前端页面读取这些文件动态渲染，改完刷新即生效。

---

## 阶段 0｜检测新角色（入口）

| 项目 | 说明 |
|---|---|
| 数据来源 | `https://umamusume.jp/character/`（按页面内 `/character/{id}` 链接的出现顺序解析）|
| 对比基准 | `data/character_index_data.js` 里现有 `id` 列表 |
| 输出 | 尚未进入 `data/character_index_data.js` 的官方角色 `id` 清单 |

脚本随后读取每个官方角色页的标题取得日文名，用它在萌娘百科登场人物页定位对应区块；中文名、CV
和详情字段都以该萌娘百科区块为准。

角色入库以萌娘百科登场人物页已经提供对应条目和中文名为数据就绪条件。阶段 0 使用
uma_tools/check_new_characters.py 检测官方新增角色，并结合登场人物页解析结果生成待处理清单

## 阶段 1｜新角色入库（官方侧素材）

| 步骤 | 目标 | 说明 |
|---|---|---|
| 1.1 | `uma_official/{id}.png` | **卡片图**：从官方角色页提取 `{cid}_01.png`，按现有卡片高度缩放后保存 |
| 1.2 | `uma_avatars/{id}.png` | 圆形头像：官方 `{cid}_icon.png`（200×200）|
| 1.3 | `data/character_index_data.js` | 追加条目：`id / zh / ja / en / cv_zh / cv / img / page(萌百链接) / main / sub` |

- **顺序必须与官方站一致**：追加后按官方页 id 出现顺序对整个 CHAR_INDEX 重排
- **中文名/CV**：从萌百登场人物页提取（如 エフフォーリア=乐透心、ファレノプシス=蝴蝶兰）；CV即使官方未发表，萌百也可能已收录（如浅见春那）
- **main/sub 颜色**：`main` 取萌娘百科登场人物页的主题色，`sub` 当前使用白色默认值

## 阶段 1.5｜萌百立绘（角色详情用）

| 目标 | 说明 |
|---|---|
| `uma_moe/{id}.png` | 萌百登场人物页该角色的立绘原图（`UPDCH_XX_00.png`，去掉`!/fw/300`等缩放参数取原图），压缩至宽600，**保留透明通道** |
| `uma_avatars/{id}.png` | 默认使用阶段1下载的官方 `{cid}_icon.png`；需要自定义裁切时可另行运行 `uma_tools/make_avatar.py` 覆盖 |

### 可选头像生成规范（make_avatar.py）

```
python3 uma_tools/make_avatar.py <cid> <透明立绘路径> [窗边长覆盖值]
```

1. 自动定位：头顶(首个非空行)/脸宽(顶部12%内最大跨度)/肩线(跨度>脸宽1.9倍处)
2. 方窗边长 = max(脸宽/0.55, 肩线距×1.15)，可按角色覆盖（如真诚=440）
3. 窗口 ×1.2 显示放大，头中心(头顶与肩线35%处)对齐画布中心
4. 主色圆底 d=195（四周留边）+ **右下投影**(高斯模糊) + 圆形软边蒙版
5. 800×800 超采样合成 → LANCZOS 缩至 200

长发铺开型立绘（如真诚）使用手动窗边长覆盖值，并在生成后检查头像构图

uma_moe/ 保存下载后的透明立绘原件。头像生成在临时副本上完成，产物写入 uma_avatars/，从而保持
详情页立绘的 600×1056 尺寸和透明通道

## 阶段 3｜血统数据（事实维护 + 自动派生）

| 步骤 | 来源 | 输出 |
|---|---|---|
| 3.1 亲本事实与角色映射 | **JBIS-Search** 与 **netkeiba** 的具体赛马血统页；已确认的角色原型对应关系 | data/pedigree_source.json |
| 3.2 生成浏览器数据 | 上一步源数据 + `data/character_index_data.js` | `python3 uma_tools/build_pedigree.py` → `data/pedigree_data.js`（PED_REL）|
| 3.3 数据校验 | 源数据、角色索引与生成结果交叉检查 | `python3 uma_tools/check_pedigree.py` |

维护时只手工修改 `data/pedigree_source.json` 中的明确事实，不直接编辑派生关系：

- 祖先完整上溯三代，缺少角色页的现实马仍保留为节点；
- 兄弟姐妹只派生同父或同母且已有角色页的对象；
- 后代只派生两代内已有角色页的对象，路径中的非角色中间代完整保留；
- 配种对象随上述可见后代路径派生，记录关系对象和关联路径。

马名跨站匹配以赛马记录、出生信息和直接父母组合共同确认。当前源数据包含 517 条已核验的直接亲本
记录：131 条标记为 jbis，386 条标记为 netkeiba 并保存具体 source_url。160 个赛马角色映射
统一使用 kind: "horse"，角色名与原型马名不同的情况通过节点名称和 real_name 表达

data/pedigree_data.js 同时提供当前角色详情页使用的三代祖先、子代和孙代字段，以及 #5 可视化使用的
character_relations。全局血统页当前加载 pedigree_assets/global-pedigree-2026.svg；role_svgs/
保存单角色血统 SVG 历史资源。#5 可直接基于 character_relations 制作复杂角色 demo 和最终交互层

## 阶段 4｜新声优（由新角色的 CV 驱动）

**增量队列** = `CHAR_INDEX` 中出现过、但 `data/va_photos_data.js` 里没有的 `cv_zh`。

照片抓取优先级：

| 优先级 | 来源 | 取什么 |
|---|---|---|
| ① | 萌娘百科（pageimages缩略图）| 照片 + infobox生日 |
| ② | 所属事务所官网 og:image | 正式宣材照 |
| ③ | 推特头像（unavatar/wsrv代理）或手动 | 头像 |

处理规范：

- 统一压缩为 **300px 宽 JPEG q75** → `uma_va/va_{声优名}.jpg`
- 追加 `data/va_photos_data.js`：`{cv_zh: {img, page, title, birth}}`
- **卡片**：前端 `vaList()` / `renderVoiceList()` 动态生成，无需改 HTML
- **担当角色关联**：自动反查 CHAR_INDEX 中该 CV 的全部角色，详情链接指向 `/database/characters/{id}`；原声优（换过CV的角色）自动带 `原` 徽标
- 特殊情况：换过声优的角色在数据里填 `cv_former`(简体)/`cv_former_ja`(日文)
