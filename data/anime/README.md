# 动漫资料主数据

本目录保存 #11 动漫资料库的人工确认数据。运行时页面只读取由这些文件确定性生成的
`data/anime_catalog.json` 和 `data/anime_relation_index.json`。

## 数据边界

- `works.json`：作品级固定资产，包括稳定 ID、中文简介、主视觉与状态。
- `units.json`：正篇、OVA、短篇和电影本篇。连续作品允许用紧凑的 `series` 声明，生成器会展开为稳定单元。
- `watch_resources.json`：观看与发行入口。只收录有实际观看价值的官方、授权或精选民间资源。
- `relations.json`：作品或内容单元到站内实体的人工确认关系。
- `staff.json`：作品级与逐集署名；保留原文职务、顺序、分组和本次署名的机构。
- `people.json`：实际动画制作人员。音乐制作人员关联已有创作者 ID，机构只作为标签。
- `source_registry.json`：主数据使用的来源注册表。
- `ending_credits.json`：已逐页核对的官方单集片尾，保存原始岗位、署名、机构和视频时间。
- `episode_cast.json`：公开逐集配音转录，按具体单集保存，来源性质独立标注。
- `excluded_extra_cast.json`：已排除的泛称龙套原始记录，不进入正式角色或声优关系。
- `overrides.json`：人工覆盖与稳定映射，目前保留为空对象供后续使用。
- `source_snapshots/` 与 `update_candidates.json`：自动观测层；采集器只能更新这两处，不能覆盖上述主数据。

## 维护命令

```bash
python3 uma_tools/build_anime_catalog.py
python3 uma_tools/build_anime_catalog.py --check
python3 uma_tools/update_anime.py --check
```

中文名称、简介、资源标签、正式关系与排序都是固定资产。自动更新只报告差异候选，应用候选必须人工修改对应主数据。

## 资料口径

作品 Cast 与逐集 Cast 分开保存。逐集 Cast 只接受官方明确披露的当集署名，不能把作品总 Cast 复制到每一集。职员表按本次署名保存人物、职务和机构；机构没有独立人物页，也不表示人物的永久所属。作品级制作人员和逐集片尾署名分别呈现。

音乐关系区分作品、单集、歌曲录音版本、专辑与实际用途。背景配乐在作品层关联公开发行曲目；逐集使用关系只接受官方、制作方或萌娘百科的明确记载，不通过听辨、曲名或曲目顺序推断。赛事的作品映射证据与现实比赛事实来源分别记录，比赛链接指向站外详情。

同名但不同作品的配乐按独立歌曲收录，发行录音按具体专辑区分，作曲署名不能跨作品或版本继承。公开转录中的脚注、停播说明和栏目标题不属于人员署名；机构分组在来源的分隔处结束。来源使用的未识别外字保留原署名，不据此创建或关联人物身份。

官方剧情页、CMS 和公开视频提供作品信息、已公开剧集、署名和全部可定位的官方剧照。公开职员表转录用于补充资料，保留来源并标明不完整；不能因转录条目很多就标记为完整片尾。图片来源登记在 `asset_sources` 中。

## 当前覆盖（2026-10-05）

收录 11 部作品、125 个已公开内容单元，全部具有中文剧情简介。110 个单元具有逐集角色关系，其中包含公开转录和官方资料，不能全部视作已核对原始片尾。逐集职员表有 39 个完整片尾、53 个不完整的公开转录、12 个主要制作人员名单、1 个主要名单及制作方补充记录，另外 20 个尚未取得逐集职员表；作品总 Staff 不能填补这些缺口。

职员表缺口集中于《赛马娘四格》其余9集电视版及11集发行新作；第三季以官网主要岗位为基础，第13话另取得STUDIO KASA的具体人员与岗位记录，其余长篇转录也保留不完整状态。RTTT剧场再编辑版使用实际剧场主创、海报、剧照与发行资料；网络版逐集片尾不能视作电影完整职员表。新增具名配角仍有缺图与简介待补，资料核查尚未完成。

已核查官网历代归档、官方 CMS、官方视频片尾、制作方资料、公开职员表转录和萌娘百科。其他公开视频未能取得完整片尾，部分资料站公开访问返回 403，动画@wiki的第三季与四格页面要求会员身份，因此相应单元继续标明资料缺口。补充时须核对具体单元和完整片尾，不能用季度名单替代。
