# 动漫资料主数据

本目录保存 #11 动漫资料库的人工确认数据。生成器产出完整的
`data/anime_catalog.json` 和 `data/anime_relation_index.json`；服务端从完整目录提供按目录、
作品、人物和关系范围读取的运行时接口，页面按需加载显示字段。证据与原始署名保留在主数据中。

## 数据边界

- `works.json`：作品级固定资产，包括稳定 ID、中文简介、主视觉与状态。
- `units.json`：正篇、OVA、短篇和电影本篇。连续作品允许用紧凑的 `series` 声明，生成器会展开为稳定单元。
- `watch_resources.json`：观看与发行入口。只收录官方与授权平台，会员内容也保留对应链接。
- `relations.json`：作品或内容单元到站内实体的人工确认关系。
- `staff.json`：作品级与逐集署名；保留原文职务、顺序、分组和本次署名的机构。
- `people.json`：实际动画制作人员。音乐制作人员关联已有创作者 ID，机构只作为标签。
- `source_registry.json`：主数据使用的来源注册表。
- `ending_credits.json`：已逐页核对的原始单集片尾，保存原始岗位、署名、机构和视频时间；资料用副本的托管来源独立记录，不冒充官方发布。
- `episode_cast.json`：公开逐集配音转录，按具体单集保存，来源性质独立标注。
- `excluded_extra_cast.json`：已排除的泛称龙套原始记录，不进入正式角色或声优关系。
- `overrides.json`：人工覆盖与已确认的角色排除名单，所有角色和逐集导入遵循相同范围。
- `source_snapshots/` 与 `update_candidates.json`：自动观测层；采集器只能更新这两处，不能覆盖上述主数据。

单集官方观测快照的 `field_status` 逐字段记录 `observed`（来源返回内容）、
`confirmed_empty`（来源明确完成该字段核查且为空）或 `unknown`（来源未返回该字段、解析器未覆盖
该字段或无法证明为空）。解析器得到的空字符串或空数组默认是 `unknown`，未知不等于没有资料。
候选只提示来源字段变化；联网源失败时保留旧快照和未处理候选，不能据此覆盖已接受记录。
候选文件中的 `accepted_coverage` 使用已展开的公开单元和现有关系统计标题、简介、音乐、角色、
职员、官方观看入口和高清剧照；没有证据的字段记为 `unknown`。职员与配音的核查状态分别来自
各自的资料，不由另一类资料推断，剧照缺少高清证据时也不补造图片。

## 维护命令

```bash
python3 uma_tools/build_anime_catalog.py
python3 uma_tools/build_anime_catalog.py --check
python3 uma_tools/update_anime.py --check
python3 uma_tools/update_anime.py --observe
python3 uma_tools/update_anime.py --observe --check-links
python3 uma_tools/complete_anime_music_relations.py --write
python3 uma_tools/reconcile_anime_music_recordings.py --write
python3 uma_tools/complete_anime_horse_profiles.py --refresh-major --write
```

中文名称、简介、资源标签、正式关系与排序都是固定资产。自动更新只报告差异候选，应用候选必须人工修改对应主数据。

`update_anime.py --check` 只检查本地目录、观测快照和候选文件，不联网；需要明确联网观察时使用
`--observe`（`--refresh` 保留为同义的刷新命令）。观察只写入 `source_snapshots/` 和
`update_candidates.json`，不会自动修改已接受主数据。`--check-links` 只检查官方观看链接的
HTTP 可达性，并将结果区分为可达、需要登录或可能受地区/权限影响、临时失败、失效和未确认；
HTTP 200 不代表完整播放可用，也不会因为检查结果自动删除观看入口。

## 资料口径

作品 Cast 与逐集 Cast 分开保存。逐集 Cast 只接受官方明确披露的当集署名，不能把作品总 Cast 复制到每一集。职员表按本次署名保存人物、职务和机构；机构没有独立人物页，也不表示人物的永久所属。作品级制作人员和逐集片尾署名分别呈现。

非官方片源仅用于核对实际片头、片尾的角色、制作人员和音乐署名，不进入观看入口，也不用于提供剧照。核对须确认作品、集数与版本，并保留副本的真实来源；剪掉片尾或无法读清的副本不作为完整名单证据。前台观看入口只采用官方与授权平台，不以是否需要会员决定收录。

单集与电影剧照统一使用 `url` 保存页面显示图、`original` 保存高清原图。资料补录、目录构建、剧集缩略图和图片查看器使用同一组字段，不在展示层保留 `thumb` 或 `original_url` 的第二套写法。

音乐关系区分作品、单集、歌曲录音版本、专辑与实际用途。背景配乐在作品层关联公开发行曲目；逐集使用关系只接受官方、制作方或萌娘百科的明确记载，不通过听辨、曲名或曲目顺序推断。赛事的作品映射证据与现实比赛事实来源分别记录，比赛链接指向站外详情。

明确到单集的比赛号角、插曲和背景配乐署名保存在 `units.json` 的 `music_cues`，保留曲名、使用类型、岗位、创作者、机构和证据。可明确对应已有曲目时连接歌曲页，未确认具体录音时不编造录音或专辑。创作者通过实际音乐使用关联回剧集；只有真正的动画制作署名进入制作人员索引。同名录音以实际演唱与发行资料判断，第一季和第二季第13话的《うまぴょい伝説》TV Size分别保存，第一季单曲与原声发行共用已确认的同一录音。

同名但不同作品的配乐按独立歌曲收录，发行录音按具体专辑区分，作曲署名不能跨作品或版本继承。公开转录中的脚注、停播说明和栏目标题不属于人员署名；机构分组在来源的分隔处结束。来源使用的未识别外字保留原署名，不据此创建或关联人物身份。

官方剧情页、CMS 和公开视频提供作品信息、已公开剧集和署名。剧照仅收录官方发布的高清场景图，采用原图至少1280×720的尺寸要求；没有高清官方剧照时不展示该栏目。视频截帧、海报和宣传插画不充当官方剧照。公开职员表转录用于补充资料，保留来源并标明不完整；不能因转录条目很多就标记为完整片尾。图片来源登记在 `asset_sources` 中。
